# Artifact Submission Plan

This directory records the artifact layout for the SPEC 6XX FireSim runs.
It intentionally keeps large binaries out of normal Git history.

## Scope

The artifact consists of four groups:

- Source snapshots for the local OpenSBI and Linux trees used by FireMarshal.
- Scripts and configuration files required to run SPEC CPU2017 speed benchmarks
  600, 602, 605, 620, 623, 631, 641, and 648.
- Sparse FireMarshal disk images for the same SPEC 6XX workloads.
- The currently active FireSim bitstream bundle and matching host driver
  bundle referenced by `sims/firesim/deploy/config_hwdb.yaml`.

The RTL source snapshot is stored under `artifact_submission/rtl/`. It is
kept source-only and is not generated by `pack_artifact.sh`.

## RTL and Embench Environment

RTL overlay:

```bash

cd /path/to/chipyard-work
source ./env.sh
export CHIPYARD_ARTIFACT_SMALLBOOM_ONLY=1
```

Reference versions for Verilator, `riscv64-unknown-elf-gcc`, Python, Java, sbt,
and Make are recorded in `ENVIRONMENT.md`. The detailed RTL flow is documented
in `rtl/README.md`.

## GitHub Storage Policy

Use normal Git only for text, scripts, manifests, and small configuration
files. Do not commit raw SPEC images or Vivado implementation directories.
GitHub warns on normal repository files larger than 50 MiB and blocks files
larger than 100 MiB. GitHub Releases support up to 1000 assets per release,
with each asset under 2 GiB.

Official references:

- https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github
- https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases

Recommended layout:

- Commit this `artifact_submission/` directory.
- Commit or transplant the small files generated under
  `artifact_submission/dist/repo-files/` into the final artifact repository.
- Keep the source-only RTL snapshot under `artifact_submission/rtl/`.
- Upload files generated under `artifact_submission/dist/release-assets/` as
  GitHub Release assets.
- Keep each release asset below 2 GiB. This matches GitHub's release asset
  per-file limit and also keeps downloads manageable.
- Git LFS is an acceptable fallback for files below the plan-specific LFS file
  limit, but release assets are preferred for review artifacts because they do
  not require reviewers to install Git LFS.

## Build The Artifact Staging Area

From the Chipyard root:

```bash
./artifact_submission/pack_artifact.sh
```

The script creates:

- `artifact_submission/dist/repo-files/`: small files that can be committed.
- `artifact_submission/dist/release-assets/`: source snapshots, sparse SPEC
  image archives, and the bitstream bundle for a GitHub Release.
- `artifact_submission/dist/checksums.sha256`: checksums for release assets.
- `artifact_submission/dist/manifest.tsv`: generated manifest with sizes and
  storage class.

`artifact_submission/dist/` is ignored by Git on purpose. Treat it as a local
staging area. Each run clears and regenerates `dist/repo-files/` and
`dist/release-assets/`, so stale assets from older benchmark sets are removed.

To skip packaging the SPEC images while testing the script:

```bash
SKIP_SPEC_IMAGES=1 ./artifact_submission/pack_artifact.sh
```

## Reviewer Restore Sketch

After cloning the artifact repository and downloading release assets:

```bash
mkdir -p external
tar -xf release-assets/opensbi-e60248380a6a.tar.gz -C external
tar -xf release-assets/linux-671eb8b7a4bd.tar.gz -C external
tar -xf release-assets/spec2017-source-snapshot.tar.gz -C external
zstd -dc release-assets/spec17-intspeed-test-600.img.tar.zst | tar -xf - -C /path/to/firemarshal/images/firechip/spec17-intspeed-test-600
```

Then place or reference the bitstream and driver bundles in `config_hwdb.yaml`:

```yaml
my_boom_bypass:
    bitstream_tar: file:///absolute/path/to/firesim-my_boom_bypass-2026-06-09.tar.gz
    driver_tar: file:///absolute/path/to/firesim-my_boom_bypass-2026-06-09-driver-bundle.tar.gz
```

Run one benchmark:

```bash
cd /path/to/chipyard
SPEC_SKIP_COMPILE=1 SPEC_MON_PROTECTED=1 ./spec17_firesim.sh run 602 test
```
